# H2 Gauge 0.4.48 — BLE GATT-сервер для CAN-over-BLE

Тестовая сборка. Ещё не опубликована: метки нет, Release нет.

## Что нового

**BLE GATT-сервер на ESP32-S3 (H2 Gauge).** Прибор теперь принимает CAN-кадры от ESP32-C3 CAN listener по BLE. Те же UUID, что и на listener-стороне:

- Сервис: `4fafc201-1fb5-459e-8fcc-c5c9c331914b`
- Characteristic: `beb5483e-36e1-4688-b7f5-ea07361b26a8` (WRITE)

Каждый BLE-пакет переносит один CAN-кадр в формате
`[seq_hi:1][seq_lo:1][ms:4][id:4][len:1][flags:1][data:0..8]`
(`flags`: bit0 = extended, bit1 = RTR). На стороне S3 реализовано:

- приём и разбор пакетов с защитой от чтения за пределы буфера;
- детектирование потерь по номеру последовательности (seq-based loss detection);
- отдельные счётчики: принято (`bleRxFrames`), потеряно по seq (`bleLostFrames`), вытеснено из очереди (`bleDroppedFrames`), отброшено из-за смены сессии (`bleStaleSessionFrames`);
- переподключение с сбросом состояния последовательности — первый кадр новой сессии не считается потерей;
- ограничение обработки до 16 кадров за цикл `loop()` — защита от голодания остальных подсистем;
- индикатор BLE на статус-行е (зелёная точка + "BLE" + hex-ID последнего кадра).

## Исправления

- Версия базовой прошивки и всех экспериментальных сборок (diagnostic, diaglong, speed-density) поднята с 0.4.47 на 0.4.48.
- Среда сборки в `.github/workflows/release.yml` приведена к `.github/workflows/platformio.yml`: `ubuntu-24.04`, `actions/checkout@v7`, `actions/setup-python@v7` с Python 3.12, pinned PlatformIO из `requirements-dev.txt` (`platformio==6.1.18`). Устранено возможное расхождение инструментов между пушем и `workflow_dispatch`.
- Все межзадачные синхронизации в BLE GATT-сервере защищены `queueMux_`: чтение и запись статистики, флаг подключения, состояние очереди.

## Что осталось прежним

- Весь функционал 0.4.47 без изменений: пиковый наддув с удержанием, подсветка по времени суток, все настройки на месте, конфиг мигрирует со схемы 15 на 15 сам, без сброса и без потери значений.
- Все прочие настройки на месте.

## Что проверить в машине

1. Включите ESP32-C3 CAN listener, подключите его по BLE к ESP32-S3 H2 Gauge.
2. На экране прибора в статус-行е загорится зелёная "BLE" с ID последнего CAN-кадра.
3. Убедиться, что при переподключении C3 не возникает ложных сообщений о потерях кадров.
4. Проверить работу портала: сохранение настроек, переключение вкладок, Wi-Fi STA.
5. Проверить, что все настройки сохранились после перезагрузки.

## Известные ограничения

- Это **тестовая** сборка. Основной выпуск остаётся 0.4.45.
- БLE-кадры пока не декодируются в физические показатели (обороты, скорость и т.д.) — сырые CAN-ID и данные отображаются в диагностике, полное декодирование требует отдельного vehicle-specific CAN ID mapping.
- Реальное испытание двух плат (ESP32-C3 + ESP32-S3) ещё не проведено.
