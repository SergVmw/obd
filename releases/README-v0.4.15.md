# H2 Gauge 0.4.15

Срочное исправление поверх **опубликованного** 0.4.14, который остаётся
нетронутым и доступен по метке `v0.4.14`.

Релиз не меняет поведение. Он отменяет потерю настроек, которую 0.4.14 принёс при
обновлении.

## 0.4.14 стирал настройки, и это не косметика

Заметка к 0.4.14 утверждала: «всё, кроме `obdTimeoutMs`, у вас уже совпадает с
заводскими значениями». **Это было написано без сверки со снимком.** Сверили —
расхождений **13**, не одно.

| поле | было | становилось | чем грозит |
|---|---|---|---|
| `fuel.fuelSource` | 5 (SpeedDensity) | 0 (Auto) | **расход перестаёт считаться совсем** |
| `lpg.lpgEnabled` | true | false | учёт ГБО выключается |
| `fuel.lpgCorrection` | 1.2 | 1.0 | расход по ГБО занижается на 17 % |
| `obd.speedCorrectionKph` | 5 | 0 | пробег и л/100 км изменяются |
| `display.brightnessMode` | 1 (Manual) | 3 (AlwaysDay) | режим дня/ночи |
| `display.mainCenterValue` | 2 | 0 | центр экрана |
| `display.brightnessDay` / `Night` | 92 / 15 | 82 / 26 | яркость |
| `display.pageDiagnostics` | true | false | страница диагностики |
| `boost.boostArcStyle` | 1 | 0 | вид дуги |
| `controls.lockLongWhenMoving` | false | true | блокировка кнопки |
| `obd.obdTimeoutMs` | 200 | 120 | единственный, о котором было сказано |

Про `fuelSource` отдельно. Режим Auto питается **только** из PID `0x5E` и MAF
`0x10`. На этой машине нет ни того, ни другого ни в одной маске, поэтому Auto — не
«другой расход», а `fuelValueValid = false` и нулевые литры. Проверено стендом на
настоящем `TelemetryEngine` с реальными значениями из снимка: расход не
считается, поездка не копится.

## Причина

Запись конфигурации 0.4.13 — **212 байт**. С добавлением `screenOffDelaySec` стала
**216**. `ConfigStore::begin()` принимает запись только при длине `sizeof(ConfigData)`
(216) или 200 (миграция со схемы 5). Запись в 212 байт не подходит ни под одно
условие → `loaded = false` → `config_ = defaults()`, и всё перезаписывается.

Миграция для схемы 6 была написана для схемы 5 и до этой правки о новой ничего не
знала.

## Что сделано

`ConfigStore::migrateV6()`. Запись схемы 6 — это схема 7 без одного добавленного
поля, то есть **побайтово тот же префикс**, контрольная сумма на четыре байта
раньше. Поэтому перенос делается одним `memcpy` на 208 байт, а
`screenOffDelaySec` берёт заводское значение из `defaults()`.

Раскладка закреплена двумя `static_assert` — `screenOffDelaySec` обязан лежать на
208, `checksum` на 212. Иначе следующее добавленное поле снова сломает миграцию
молча.

Тест собирает настоящую 212-байтную запись схемы 6 с отличимыми значениями и
проверяет, что пережили все настройки: яркость, ГБО, коррекция скорости, таймаут,
частота запросов, режим топлива, центр экрана, блокировка кнопки, пароль точки
доступа. Без ветки миграции тест падает на первой же яркости — проверено откатом.

`tools/test_screen_gate.py` и `tools/check_pid_names.py` существовали, проходили и

видно. Он подключён сам, включая себя.

## Срочно: если 0.4.14 уже залит

**Миграция не вернёт потерянное.** Если прибор уже работал на 0.4.14, он при
загрузке принял 212-байтную запись за негодную и **перезаписал её заводскими** —
восстанавливать нечего. Настройки надо вернуть вручную:

```
POST /api/config
{
  "display": {"brightnessDay": 92, "brightnessNight": 15, "brightnessMode": 1,
              "manualNight": true, "mainCenterValue": 2, "pageDiagnostics": true},
  "boost":   {"boostArcStyle": 1},
  "fuel":    {"fuelSource": 5, "lpgCorrection": 1.2},
  "lpg":     {"lpgEnabled": true},
  "controls":{"lockLongWhenMoving": false, "screenOffDelaySec": 60},
  "obd":     {"obdTimeoutMs": 200, "speedCorrectionKph": 5}
}
```

Недостающие поля берутся из текущих, поэтому можно передавать только изменённые.

**Как понять, затронуты ли вы.** Откройте `/api/config`: если
`fuel.fuelSource` равен 0, а не 5 — расход сейчас не считается.

**Если 0.4.14 ещё не залит — заливайте 0.4.15**, настройки переживут.

`obdTimeoutMs`: 120 заводское и прописано в workflow, 200 — то, что стояло на
машине. На ваш выбор, в приведённом JSON 200.
