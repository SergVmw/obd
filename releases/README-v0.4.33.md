# H2 Gauge 0.4.33

Релиз поверх 0.4.32 (остаётся нетронутым по метке `v0.4.32`). Config schema
обновлена до **13** (`sizeof(ConfigData) == 348`, автоматическая миграция
`migrateV12` сохраняет все 226 значащих байт схемы 12 без захвата хвостового
выравнивания `226..227`). Формат `TripState` (`88 B`) и кольцевой архив
`/trips.bin` (`148 B × 2 048 = 303 104 B`) не менялись — накопленная поездка и
вся история переносятся без потерь.

Новое — **клиентский режим Wi-Fi (`STA`, строго Read-Only) для вывода панели
приборов и истории поездок на экран Android-магнитолы через точку доступа
телефона (например, Xiaomi 14)** по адресу **`http://h2/`** или
**`http://h2.local/`**.

## 1. Архитектура, изоляция сервисного портала и безопасность режима `STA`

| Свойство | Реализация |
|---|---|
| Гарантированная изоляция `ServicePortal` (`192.168.4.1:80`) от второго веб-сервера | **Шестиуровневая защита от перехвата порта `80` в lwIP (`CONFIG_LWIP_SO_REUSE=1`):** (1) в `setup()` вызывается только бездействующий `staRuntime.attach(tripHistory)` — при входе в сервис удержанием кнопки при подаче питания (`bootService`) или при `staEnabled = false` задача `STA` вообще **никогда не создаётся**; (2) слушатель `STA` привязывается строго к конкретному внешнему IP точки доступа `WiFiServer(ip, 80, 2)` с проверкой `isSafeStaBindIp(...)` (запрет `0.0.0.0`, `127/8`, `>=224/8` и всей подсети точки доступа прибора `192.168.4.0/24`); (3) перед `servicePortal.begin()` срабатывает необратимая защёлка `shutdownForService()` — задача Core 0 мгновенно сбрасывает клиентские сокеты с `SO_LINGER={1,0}` (без накопления `TIME_WAIT` в пуле из `16` сокетов lwIP), закрывает `WiFiServer`, гасит `mDNS`, `SNTP` и `WiFi.mode(WIFI_OFF)` и удаляет себя через `vTaskDelete(nullptr)`; (4) запросы `4 Гц` идут по постоянному соединению `HTTP/1.1 keep-alive` с истинными миллисекундными таймаутами `SO_RCVTIMEO = 50 мс` / `SO_SNDTIMEO = 250 мс` (вместо секундного `WiFiClient::setTimeout`); (5) `ServicePortal::bringUpAccessPoint()` принудительно очищает состояние `STA` перед стартом `WIFI_AP`, а `ServicePortal::begin()` проверяет фактический статус слушателя `server_.listening()` с повтором; (6) аппаратный откат слота кнопкой (`DoublePress -> LongPress -> ServiceHold`) сохранён без изменений. |
| Режим доступа в `STA` | **Строго Read-Only**: принимаются исключительно `GET /`, `GET /api/ro/live`, `GET /api/ro/trips`, `GET /api/ro/trips/days`. Любой метод кроме `GET` (`POST`, `PUT`, `DELETE`, `PATCH`, `HEAD`, `OPTIONS` и др.) немедленно отклоняется по первой строке запроса кодом **`405 Method Not Allowed`** (`Allow: GET`, `Connection: close`) без чтения и выделения памяти под `Content-Length`. Любой иной путь — **`404 Not Found`**. Изменение настроек, сброс истории и OTA-обновление остаются исключительно в сервисном режиме `AP` по удержанию кнопки `5 с`. |
| Изоляция ядер и CAN | Сетевой стек `WiFi`, `mDNS`, `SNTP` и HTTP-сервер исполняются в отдельной FreeRTOS-задаче `"h2-sta-http"` на **Core 0** (`8 192 B` стека). Основной цикл CAN/OBD и отрисовки `240×240` остаётся на **Core 1**; очередь приёма `TWAI` увеличена с `20` до **`64`** кадров (`rx_queue_len = 64`), все обращения к `LittleFS` сериализованы рекурсивным мьютексом `StorageLock`. |
| Сон радиомодуля | **Строго вместе с экраном (`strict_screen`)**: как только `screenGate.dark()` становится `true` (стоянка / тишина ЭБУ) либо выполняется вход в сервисный режим `AP` / глубокий сон по низкому напряжению, задача на Core 0 останавливает HTTP, `mDNS` и `SNTP` и переводит радиомодуль в **`WiFi.mode(WIFI_OFF)`** (`0 мА` на радио). В `WiFi.persistent(false)` запрещена запись учётных данных во флеш драйвером ESP-IDF при каждом пробуждении. |
| Бережный повтор при отсутствии телефона | Таймаут попытки подключения `10 с`, ступенчатый интервал между попытками **`5 → 15 → 30 с`** с включённым modem-sleep (`WiFi.setSleep(true)`), чтобы не мешать Bluetooth-профилям телефона на `2,4 ГГц`. |
| Автоматическое имя узла и точное время | `WiFi.setHostname(host)` выставляется до и сразу после `WiFi.mode(WIFI_STA)` (DHCP Option 12 для `http://h2/` в `dnsmasq` точки доступа Android) плюс `MDNS.begin(host)` (`http://h2.local/`). При появлении интернета `SNTP` синхронизирует UTC в ОЗУ за `< 1 мкс` (`TripClock::syncRamOnly`) без записи во флеш на ходу, ретроспективно проставляет точное время старта уже начатой поездки по монотонному счётчику RTC и сохраняет якорь в NVS после остановки автомобиля. |
| Индикация на экране `240×240` | При `staEnabled = true` нижняя строка экрана «Диагностика» (стр. 4) показывает `IP x.x.x.x`, `WIFI: ПОИСК` или `WIFI: ВЫКЛ`; при `staEnabled = false` сохраняется прежняя строка `VIN`. |

## 2. Панель магнитолы (`web/headunit.html`, `10 702 B` gzip в `PROGMEM`)

Адаптивный интерфейс без внешних шрифтов и CDN (работает полностью офлайн внутри
локальной подсети телефона, проверен на `1280×720`, `1024×600` и `400×820`
Xiaomi 14):

- **Переключатель `[Вид: Стрелки / Цифры]`** (сохраняется в `localStorage`) и
  живой опрос `/api/ro/live` с частотой **`4 Гц` (`250 мс`)**.
- **6 векторных `230°` шкал SVG там, где работает периферическое зрение:**
  1. **Экономайзер (`0..30 л/100 км`)** с подвижным треугольным маркером `▲`
     среднего расхода в движении (левее метки — экономия топлива);
  2. **Наддув / разряжение (`-1.0..+1.5 бар`)** с маркером пикового наддува `▲`;
  3. **Тахометр (`0..6000 об/мин`)**;
  4. **Температура ОЖ (`50..130 °C`)** — рабочие **`90 °C` строго на 12 часах (`0°`)**;
  5. **Напряжение бортсети ЭБУ (`11.0..15.5 В`)**;
  6. **Биполярная сумма топливных коррекций `STFT + LTFT` (`-25..+25 %`)** — **`0 %` строго на 12 часах (`0°`)**.
- **4 вкладки с кнопками `≥ 44 px`:** «Текущая», «Двигатель» (`PID 03` выводится
  честным сырым байтом `0x..` без домысливания полярности ревизий J1979, `PID 14`
  с шагом `0,00495 В/бит`, баннер `CHECK Pxxxx` при активной ошибке), «Поездки»
  (с раскрытием раздельного баланса Бензин / ГБО) и «По дням».
