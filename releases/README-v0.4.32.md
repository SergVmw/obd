Релиз поверх 0.4.31. Config schema **12** не менялась (`sizeof(ConfigData) == 232`),
формат `TripState` (`88 B`) и `/trips.bin` (`148 B × 2 048`) не менялись —
накопленная поездка, архив и все настройки переносятся без миграции.

Новое — **просмотр истории поездок прямо на круглом экране `240×240` с экрана
«Расход» (стр. 1)** без входа в сервисный режим, без остановки CAN-опроса и без
обращений к LittleFS во время отрисовки.

## 1. Управление одной кнопкой на экране «Расход» (стр. 1)

| Жест | Поведение |
|---|---|
| Короткое нажатие на «Расходе» | Обычный переход на следующую страницу (`0 мс` задержки, пропуск нескольких страниц быстрыми нажатиями сохранён) |
| **Длинное нажатие на «Расходе»** | **Открывает режим «История»** (подчиняется настройке `lockLongWhenMoving`; случайное стирание текущей поездки с кнопки исключено — ручной сброс остаётся в веб-портале) |
| Короткое нажатие внутри «Истории» | Листает карточки по кругу: **`Сутки` → `#N` → `#N-1` → … → `#N-15` → `Сутки`** (если архив ещё пуст — сразу выходит обратно на «Расход») |
| Длинное нажатие внутри «Истории» | Мгновенный выход обратно на экран «Расход» (работает всегда, даже в движении) |
| **15 секунд без нажатий** | Автоматический возврат на экран «Расход» |
| 4 быстрых нажатия (ручная яркость) | Переключает День / Ночь и продлевает таймер просмотра |
| Удержание сервисного входа | Штатно закрывает просмотр и открывает сервисный режим на стоянке |

На главном экране (стр. `0`) длинное нажатие по-прежнему сбрасывает пиковый наддув.

## 2. Компоновка карточек под круг `240×240` и шрифты VLW

Все подписи проверены по таблицам ширины глифов `H2GolosSmall13`,
`H2GolosMedium19`, `H2GolosDigits38` и физическим хордам круглого дисплея
(`2 · √(120² − (y − 120)²)`), без символов вне кодовой таблицы шрифта:

| Полоса (`y`) | Шрифт | Содержимое |
|---|---|---|
| `y = 28` | `Medium19` | **`ИСТОРИЯ`** (`93 px` в хорде `154 px`) |
| `y = 56` | `Small13` | Карточка суток: **`СЕГОДНЯ DD.MM | N П.`** (если дата совпадает с текущими синхронизированными часами) или **`СУТКИ DD.MM | N П.`**<br>Карточка поездки: **`#48 | 21.10 | 46 М`** (без часов: **`#48 | БЕЗ ДАТЫ | 46 М`**) |
| `y = 100` | `Digits38` | Пробег крупно: **`34.6`** |
| `y = 131` | `Small13` | Единица и взвешенный средний расход: **`КМ | 8.4 Л/100`** (при `< 0.1 км`: **`КМ | ПРОГРЕВ`**) |
| `y = 169 / 188` | `Medium19` + `Small13` | Слева (`x = 68`, цвет `colorWarning`): **`0.42 л`** / `БЕНЗИН`<br>Справа (`x = 172`, цвет `colorBoost`): **`2.91 л`** / `ГАЗ` |
| `y = 211` | `Small13` + `fillCircle` | Индикатор позиции **`СУТКИ`** / **`1 ИЗ 16` … `16 ИЗ 16`** с круглыми маркерами |

Записи с `dateUnknown = true` никогда не подмешиваются в суточную карточку, но
честно отображаются при листании отдельных поездок с отметкой **`БЕЗ ДАТЫ`**.

## 3. RAM-кэш без чтения LittleFS в `loop()` / `render()`

- `TripHistoryView` хранит в статической памяти готовый срез последних **`16`**
  закрытых поездок и взвешенной сводки последнего датированного дня (`~2,4 КБ`
  SRAM, без динамических аллокаций в куче).
- `TripHistory::readRecentAndLatestDay()` читает с конца кольца только свежий
  хвост вместо полного обхода всех `2 048` слотов и даёт **побайтово идентичную**
  суточную сводку полному `readDays(1, ...)`.
- Счётчик поколений `TripHistory::generation()` обновляет кэш за одну проверку
  `uint32_t` только тогда, когда реально изменился архив (`begin`, `append`,
  `clear`), поэтому во время отрисовки обращений к LittleFS **ноль (`0 мс`)**, а
  CAN-опрос и учёт текущей поездки не прерываются ни на миллисекунду.
