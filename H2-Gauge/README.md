# H2 Gauge

Первая программная ревизия автомобильного круглого информационного прибора для **Haval H2 2018 1.5T** с ГБО **BRC Sequent 32 EVO OBD**.

- MCU: ESP32 DevKit V1 / ESP32-WROOM-32
- Display: GC9A01 240×240
- Vehicle data: ESP32 TWAI + внешний 3.3-вольтовый CAN-трансивер
- OBD: ISO 15765-4, 11-bit, начальная скорость 500 кбит/с
- LPG state: защищённый вход клапана на GPIO34 (по умолчанию отключён)
- Configuration: локальный Wi-Fi service portal

## Статус revision 0.1.9

Исправление 0.1.1: полноэкранный framebuffer переключён с RGB565 16-bit (115200 байт) на 8-bit (57600 байт), поскольку на ESP32-WROOM без PSRAM не удалось выделить один непрерывный 16-bit блок. В таблицу разделов добавлен Core Dump 64 КиБ.

Исправление 0.1.2: на экране `FUEL / TRIP` строка пробега перенесена из нижней статусной области в заголовок, чтобы исключить наложение на индикаторы `95/LPG` и `OBD`.

Добавление 0.1.3: стартовый красный логотип HAVAL плавно проявляется. Изображение занимает 16 416 байт Flash и выводится построчно через временный RAM-буфер 432 байта, поэтому не мешает выделению основного 8-bit framebuffer.

Исправление 0.1.4: стартовая заставка длится ровно около 2 секунд, из них 1,5 секунды занимает плавное проявление. GPIO26 переводит GC9A01 в аппаратный reset в самом начале `setup()`, поэтому предыдущая шкала больше не остаётся на экране во время программной инициализации ESP32.

Добавление 0.1.5: в сервисной панели появились настройки цветов цифр, вакуума, наддува, предупреждения и опасной зоны, а также выбор вида шкалы турбо. Цвета хранятся в NVS как RGB565. Схема конфигурации повышена до версии 2, поэтому при первом запуске 0.1.5+ прежняя конфигурация будет один раз заменена обновлёнными значениями по умолчанию.

Исправление 0.1.6: сплошная шкала теперь рисуется настоящей непрерывной дугой толщиной 8 пикселей средствами `drawArc`, а не увеличенным количеством радиальных рисок. Во встроенную сервисную панель добавлен интерактивный круглый предпросмотр с тестовым наддувом, режимом LPG/95, всеми пользовательскими цветами и обоими видами шкалы. Известное предупреждение TFT_eSPI о `TOUCH_CS` подавлено в конфигурации сборки.

Добавление 0.1.7: все рабочие страницы прибора получили тёмный фон с диагональным плетением под карбон. Узор строится небольшими примитивами непосредственно в существующем 8-bit framebuffer и не требует второго буфера или фоновой bitmap. Текст переведён на прозрачный фон, чтобы вокруг символов не появлялись однотонные прямоугольники. Такой же карбоновый фон добавлен в интерактивный веб-предпросмотр.

Добавление 0.1.8: шкала наддува расширена почти до физической кромки круглого дисплея — внешний радиус 116 пикселей. В сервисной панели можно выбрать центральное значение главного экрана: наддув, скорость, текущий расход или средний расход текущего топлива. Средний расход автоматически переключается между отдельными накопителями бензина и LPG. Добавлен выбор языка надписей прибора (`Русский`/`English`) и компактный встроенный шрифт DejaVu Sans Bold с кириллицей. Заводской автовозврат на главный экран изменён на 5 секунд. Веб-панель сначала заполняет форму встроенными defaults, затем заменяет их сохранённой конфигурацией ESP32; добавлена отдельная кнопка загрузки заводских значений в форму. Настройки 0.1.7 сохраняются благодаря упаковке новых параметров в свободные биты существующего поля NVS.

Добавление 0.1.9: свежий PID 42 контролирует low-voltage policy — ниже 11.5 В в течение 3 секунд trip принудительно сохраняется, TWAI и дисплей останавливаются, затем ESP32 уходит в deep sleep с пробуждением через 30 секунд или кнопкой GPIO32. Усиллено автоматическое восстановление TWAI bus-off и включён `TWAI_ALERT_AND_LOG`. Добавлены PID 11/06/07, DFCO, контроль STFT+LTFT на LPG и адаптивный polling. Создан отключённый Mode 22/ISO-TP framework без выдуманных Haval DID. Сервис получил ограниченный REST CAN Monitor с агрегацией до 32 ID/направлений. Все собственные runtime-сообщения переведены на `ESP_LOGI/W/E`; добавлены схема автомобильного питания, troubleshooting и CI-сборка GitHub Actions. Schema 3 мигрирует настройки 0.1.8 без сброса.

Реализовано:

- запуск встроенного TWAI ESP32 и автоматический bus-off recovery;
- поиск диапазонов поддерживаемых Mode 01 PID;
- чтение MAP, RPM, speed, MAF, throttle, STFT, LTFT, BARO, voltage, coolant, Fuel Rate и commanded equivalence ratio;
- расчёт относительного наддува;
- расчёт бензина по PID 5E с резервом MAF;
- расчёт LPG по MAF с отдельным коэффициентом;
- DFCO по закрытому throttle/RPM и предупреждение STFT+LTFT для LPG;
- раздельное накопление бензина и LPG;
- low-voltage deep sleep по свежему PID 42;
- отключённый расширяемый Mode 22/ISO-TP framework;
- REST CAN Monitor с фиксированной агрегацией и rate limit;
- четыре экранные страницы;
- одна кнопка;
- вход LPG через оптопару;
- NVS-конфигурация и сохранение trip;
- сервисная Wi-Fi точка и captive portal;
- настройки через веб;
- локальное app OTA через `firmware.bin`;
- встроенный gzip web UI, отдельный LittleFS для первой ревизии не требуется.

Пока не реализовано:

- физическая проверка на Haval;
- BRC K-Line/KWP2000;
- BMP280;
- фирменные Haval CAN-сигналы;
- speed-density fallback;
- подтверждённые Haval Mode 22 DID и формулы;
- подтверждённый bootloader rollback;
- полноценные кириллические smooth fonts;
- day/night automation;
- защищённая автомобильная плата питания.

## Распиновка

### GC9A01

| GC9A01 | ESP32 |
|---|---:|
| SCLK | GPIO14 |
| MOSI | GPIO13 |
| CS | GPIO33 |
| DC | GPIO27 |
| RST | GPIO26 |
| BL | GPIO25 через транзистор/MOSFET |
| VCC | 3.3 V |
| GND | GND |

Для подавления вспышки до логотипа установить 10 кОм между GPIO26/RST дисплея и GND. На текущем стенде BL/BLK подключён к 3.3 В, GPIO25 не подключён; PWM заработает только после установки аппаратного ключа подсветки.

Полная схема питания, кнопки, CAN и ключа подсветки: [`docs/wiring.md`](docs/wiring.md).

### CAN transceiver

| CAN transceiver | ESP32 / OBD |
|---|---|
| TXD | GPIO16 |
| RXD | GPIO17 |
| CAN-H | OBD pin 6 |
| CAN-L | OBD pin 14 |
| GND | ESP32 GND и OBD pin 4/5 |

Для прототипа можно использовать SN65HVD230. Не устанавливать дополнительный терминатор 120 Ом на автомобильную CAN-шину.

### Кнопка

```text
GPIO32 ── кнопка ── GND
```

### LPG input

```text
клапан → диодный мост/защита → оптопара
3.3 V → 10 кОм → GPIO34 → коллектор оптопары
GND ESP32 → эмиттер оптопары
```

GPIO34 не имеет внутренней подтяжки. В конфигурации вход LPG по умолчанию выключен до установки защищённой схемы.

## Сборка

Требуется PlatformIO.

```bash
pio run
```

Файл для OTA после локальной сборки:

```text
.pio/build/esp32dev/firmware.bin
```

Готовый release 0.1.9:

```text
releases/h2-gauge-v0.1.9-esp32.bin
SHA-256: 86d01b6aec6c0f8c39b70e18e25b3f34576ec0032d1c8dab9f8e70d9fd4d77d6
```

Первая полная прошивка по USB:

```bash
pio run --target upload
```

Serial Monitor:

```bash
pio device monitor
```

## Demo mode без автомобиля

Для проверки интерфейса без CAN временно добавить одну строку в существующий список `build_flags` файла `platformio.ini`:

```ini
    -D H2G_DEMO_MODE=1
```

После проверки удалить эту строку, чтобы вернуть реальные OBD-запросы.

В текущем demo mode имитируется скорость 72 км/ч, поэтому вход удержанием кнопки во время работы блокируется как «автомобиль движется». Для входа в сервис используйте загрузочный жест: удерживайте кнопку, нажмите `EN` или включите питание и продолжайте удерживать не менее 3 секунд.

## Сервисный режим

Вход:

- удерживать кнопку 3 секунды при включении;
- либо удерживать около 5 секунд при стоящем автомобиле.

Точка доступа:

```text
SSID: H2-Gauge-XXXX
Password default: h2gauge18
URL: http://192.168.4.1
```

Пароль нужно изменить после первой установки.

Выход — удержание кнопки или команда перезагрузки из веб-интерфейса.

## Обновление встроенного веб-интерфейса

После изменения `web/index.html` выполнить:

```bash
python3 tools/embed_web.py
pio run
```

Скрипт создаёт gzip-массив `src/web_ui_gz.h`, который входит в единый `firmware.bin`.

## OTA partitions

Используется `partitions_4mb_ota.csv`:

- APP0: 1.5 MiB
- APP1: 1.5 MiB
- Core dump: 64 KiB
- LittleFS: 896 KiB

Обычный веб-OTA принимает только app image `firmware.bin`. Не загружать через него `bootloader.bin`, `partitions.bin` или merged image.

## Важное предупреждение

Это первая непроверенная аппаратно ревизия. Перед постоянным подключением к автомобилю необходимо:

1. Проверить питание и уровни CAN-трансивера.
2. Удалить/отключить терминатор 120 Ом на модуле.
3. Питать ESP32 от USB во время первого CAN-теста.
4. Соединить общую массу с OBD pin 4/5.
5. Не подавать OBD +12 В напрямую на ESP32.
6. Проверить ответы `01 00`, `01 0B`, `01 10`, `01 33`, `01 42`, `01 5E`.
