# H2 Gauge 0.2.0 — LPG master switch, petrol full-tank calibration and speed correction

Дата: 2026-09-11. Статус: код и ESP32-сборка завершены; требуется автомобильная проверка.

## 1. Глобальный выключатель ГБО

Существующий `ConfigData::lpgEnabled` повышен из локального флага GPIO34 до **главного выключателя всех функций LPG**.

Когда `lpgEnabled=false`:

- `LpgValveInput::update()` не читает GPIO34, сбрасывает debounce candidate и возвращает `false`;
- двигатель при валидных RPM считается работающим на бензине;
- LPG fuel-rate, LPG correction и LPG trip не участвуют в отображении;
- экран расхода показывает только бензиновые литры;
- OBD polling не запрашивает PID 06/07 для контроля STFT/LTFT LPG;
- LPG trim warning гарантированно сброшен;
- API возвращает нулевое отображаемое значение LPG;
- сервисная панель скрывает AFR/density/correction, вход клапана, trim warning и LPG-калькулятор;
- preview принудительно переключается на `95`;
- оставшийся от старой конфигурации `FuelSource::BrcKLine` заменяется на `Auto`.

Бензиновые PID 5E/MAF, DFCO, текущий/средний расход, trip, бензиновая коррекция и калибровка продолжают работать независимо.

В веб-панели главный флаг называется **«Использовать ГБО»**. Заводское значение остаётся `false`, поскольку GPIO34 нельзя использовать без установленного защищённого входа и внешней подтяжки.

## 2. Калибровка бензина «полный бак → полный бак»

Добавлен отдельный постоянный `PetrolCalibrationState` в NVS namespace `h2petcal`. Он не использует и не сбрасывает обычный `TripState`.

Состояние хранит:

- active/inactive;
- сырые рассчитанные литры бензина;
- пройденный на бензине путь;
- время работы на бензине;
- количество завершённых калибровок;
- фактические и расчётные литры последнего интервала;
- прежний и новый коэффициенты.

### Рабочий процесс

1. Заправить бак до полного.
2. В сервисе нажать **«Начать новый интервал»**.
3. Ездить в обычном режиме. Если ГБО включено, в бензиновый интервал попадают только периоды `FuelMode::Petrol`.
4. При следующей полной заправке ввести литры из чека.
5. Нажать **«Заправлено до полного — рассчитать K»**.

Формула:

```text
calculated = rawPetrolLiters × oldCorrection
newCorrection = oldCorrection × actual / calculated
              = actual / rawPetrolLiters
```

Результат принимается только в диапазоне `0.5…1.5`. Интервал должен содержать минимум `0.1` расчётного сырого литра, фактическая заправка — `1…150 л`. Операции start/apply блокируются при сырой скорости PID 0D выше 3 км/ч.

После успешного применения новый `petrolCorrection` немедленно сохраняется в основном NVS. Обычная поездка и LPG-статистика не сбрасываются. Текущий активный интервал сохраняется каждые 60 секунд, перед low-voltage deep sleep и при входе в сервис.

### REST API

```text
GET  /api/fuel/petrol-calibration
POST /api/fuel/petrol-calibration/start
POST /api/fuel/petrol-calibration/apply
     {"actualLiters": 42.35}
```

`GET` возвращает active, raw/calculated liters, distance, seconds, current correction и последний результат. Factory reset очищает и trip, и отдельное состояние калибровки.

## 3. Коррекция скорости

В schema 4 добавлено `ConfigData::speedCorrectionKph`:

- диапазон `−20…+20 км/ч`;
- шаг веб-интерфейса `0.5 км/ч`;
- заводское значение по решению пользователя — `0`;
- формула: `correctedSpeed = max(0, PID_0D + correction)`.

Пример: значение `−5` уменьшает показание на 5 км/ч.

`TelemetryData` теперь раздельно хранит:

- `rawSpeedKph` — неизменённый PID 0D;
- `speedKph` — скорректированное значение.

Скорректированная скорость используется:

- на центральном индикаторе скорости;
- на странице температуры/скорости;
- для перехода л/ч ↔ л/100 км;
- для интегрирования trip/calibration distance;
- для среднего расхода.

Сырая скорость используется для safety-проверок входа в сервис, OTA, действий кнопки, start/apply калибровки и определения parked polling. Поэтому отрицательная пользовательская коррекция не может разрешить сервисную операцию на движущемся автомобиле.

`/api/status` дополнен `rawSpeedKph`, `speedKph` и `speedCorrectionKph`.

## 4. NVS schema 4

`speedCorrectionKph` добавлен в конец `ConfigData` непосредственно перед checksum. Миграция schema 2/3:

1. определяет прежний размер blob;
2. проверяет прежний FNV-1a checksum;
3. копирует весь старый prefix без сброса настроек;
4. задаёт новой коррекции скорости `0`;
5. обновляет schema/checksum и сохраняет blob нового размера.

Для уже валидной schema 4 выполняется defensive validation диапазона и finite-value. Отдельное состояние бензиновой калибровки имеет собственные magic, schema и checksum.

## 5. Сервисная панель

Раздел «Расход и ГБО» перестроен:

- главный LPG switch находится первым;
- бензиновый расчёт и full-tank calibration всегда видимы;
- LPG-only секции динамически скрываются;
- состояние калибровки обновляется REST-запросом каждые 3 секунды;
- обычный reset trip явно сообщает, что калибровочный интервал сохраняется.

В разделе OBD добавлено поле коррекции скорости и пояснение знака.

Встроенный gzip header `src/web_ui_gz.h` пересоздан из актуального `web/index.html` с deterministic `mtime=0`.

## 7. Автомобильная проверка

1. Сравнить сырой PID 0D, показание штатного спидометра и GPS на нескольких скоростях. Постоянная поправка `−5` может быть недостаточна, если ошибка пропорциональная.
2. Проверить full-tank calibration минимум на двух последовательных полных заправках одной АЗС/колонки.
3. Не включать калибровку по короткому интервалу: погрешность отсечки пистолета будет слишком большой.
4. При включённом ГБО учитывать, что бензиновый довпрыск во время LPG не определяется сигналом одного клапана и может потребовать будущего источника BRC.
5. Проверить, что при выключенном глобальном LPG switch GPIO34 и PID 06/07 не влияют на режим `95`.
