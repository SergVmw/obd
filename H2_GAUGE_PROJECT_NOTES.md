# H2 Gauge — сводка проекта и технические заметки

**Дата фиксации состояния:** 2026-09-07  
**Статус:** концепция и интерактивный веб-макет; прошивка и электрическая схема ещё не собраны.

Этот документ предназначен для переноса проекта в GitHub и продолжения работы в новом диалоге без потери контекста.

---

## 1. Цель проекта

Сделать компактный автомобильный информационный прибор на базе ESP32 и круглого дисплея, получающий основные данные двигателя через OBD2/CAN.

Основные показатели:

1. Турбонаддув.
2. Напряжение бортовой сети.
3. Текущий расход топлива.
4. Средний расход топлива.
5. Режим топлива: бензин или ГБО.

Дополнительные показатели на вспомогательных страницах:

- обороты двигателя;
- скорость;
- температура охлаждающей жидкости;
- температура воздуха на впуске;
- MAP;
- атмосферное давление;
- пиковый наддув;
- состояние OBD/CAN;
- поддерживаемые PID;
- ошибки связи;
- статистика поездки.

## 3. Ключевые принятые решения

### 3.1. CAN без MCP2515

Предпочтительная схема:

```text
ESP32 TWAI → CAN-трансивер → CAN-H / CAN-L автомобиля
```

Вместо:

```text
ESP32 → SPI → MCP2515 → CAN-трансивер → CAN-H / CAN-L
```

Преимущества встроенного TWAI:

- меньше компонентов;
- не занимает SPI;
- GC9A01 не конкурирует с CAN за шину;
- меньше задержка;
- проще добиться быстрого обновления наддува;
- нет проблемы 5-вольтовой логики типичного MCP2515/TJA1050.

Для прототипа подходит модуль **SN65HVD230** с питанием 3.3 В. Для окончательного автомобильного устройства предпочтительнее автомобильный трансивер с 3.3-вольтовой логикой, например:

- TJA1051T/3;
- MCP2562 с VIO;
- другой automotive-grade high-speed CAN transceiver.

ESP32 нельзя подключать GPIO напрямую к CAN-H и CAN-L — внешний физический CAN-трансивер обязателен.

### 3.2. Один пользовательский орган управления

На корпусе планируется **одна большая тактильная кнопка**.

Основная логика:

| Действие | Функция |
|---|---|
| Короткое нажатие | Следующий экран |
| Удержание 1.5–2 секунды | Контекстное действие |
| Удержание около 5 секунд на стоянке | Сервисный режим |
| Удержание при включении питания | Гарантированный вход в сервисный режим |
| Бездействие 8–10 секунд | Возврат на главный экран |

Длинные и потенциально опасные действия блокируются при скорости выше примерно 3 км/ч.

Рекомендуется оставить на плате площадку под вторую скрытую сервисную кнопку или контакты аппаратного сброса, но в обычной эксплуатации использовать только одну кнопку.

### 3.3. Все редкие настройки — через Wi‑Fi

В штатном режиме Wi‑Fi выключен. В сервисном режиме ESP32 создаёт локальную точку доступа и автономную веб-панель.

Пример:

```text
SSID:    H2-Gauge-4F2A
Адрес:   192.168.4.1
Пароль:  задаётся владельцем
```

На дисплее в сервисном режиме показываются:

- название сети;
- адрес страницы;
- состояние подключения;
- инструкция выхода;
- опционально QR-код.

Сервисный режим автоматически закрывается после 10–15 минут бездействия. Интернет не нужен: HTML, CSS, JavaScript и API хранятся в ESP32.

### 3.4. Определение режима ГБО

Первая версия: состояние ГБО определяется по сигналу газового электромагнитного клапана через защищённый вход и оптопару.

Вторая версия: возможное чтение данных BRC Sequent 32 EVO через его отдельный диагностический K-Line/KWP2000-интерфейс.

## 5. Предварительное распределение GPIO

### 5.1. GC9A01

Предложено использовать HSPI:

| GC9A01 | ESP32 DevKit V1 |
|---|---:|
| VCC | 3V3 |
| GND | GND |
| SCL / CLK | GPIO14 |
| SDA / MOSI | GPIO13 |
| CS | GPIO33 |
| DC | GPIO27 |
| RST / RES | GPIO26 |
| BL / BLK | через транзистор от GPIO25 |

Для первого настольного теста подсветку можно включить постоянно, если конкретный модуль допускает питание BL от 3.3 В. В окончательной схеме яркость управлять PWM через транзистор/MOSFET, а не питать светодиод подсветки напрямую от GPIO.

Предварительные настройки TFT_eSPI:

```cpp
#define GC9A01_DRIVER

#define TFT_MOSI 13
#define TFT_SCLK 14
#define TFT_CS   33
#define TFT_DC   27
#define TFT_RST  26

#define USE_HSPI_PORT
#define SPI_FREQUENCY 40000000
```

### 5.2. CAN/TWAI

| Сигнал | ESP32 |
|---|---:|
| CAN TX | GPIO16 |
| CAN RX | GPIO17 |

Для SN65HVD230:

```text
ESP32 GPIO16 → CTX / TXD / D
ESP32 GPIO17 ← CRX / RXD / R
ESP32 3V3    → VCC
ESP32 GND    → GND
CAN-H        → OBD pin 6
CAN-L        → OBD pin 14
GND          → OBD pin 4 или 5
RS           → режим high-speed, обычно к GND согласно модулю
```

На модуле CAN не должен быть подключён дополнительный терминатор 120 Ом. Автомобильная CAN-шина уже терминирована.

### 5.3. Кнопка

```text
GPIO32 ─── кнопка ─── GND
```

В прошивке:

```cpp
pinMode(32, INPUT_PULLUP);
```

Нужен программный debounce примерно 30–50 мс.

### 5.4. Вход состояния ГБО

Предварительно:

- GPIO34;
- GPIO34 является входом без внутренней подтяжки;
- нужна внешняя подтяжка 10 кОм к 3.3 В;
- активный уровень при включённой оптопаре — LOW.

```text
3.3 V
  │
 10 кОм
  │
GPIO34 ─── коллектор оптопары
             эмиттер
                │
               GND ESP32
```

## 6. Подключение к OBD2 Haval

### 6.1. Разъём

| OBD pin | Назначение |
|---:|---|
| 4 | chassis ground |
| 5 | signal ground |
| 6 | CAN-H |
| 14 | CAN-L |
| 16 | постоянный +12 В, часто даже при выключенном зажигании |

### 6.2. Предполагаемый протокол

Начальная гипотеза для Haval H2 2018:

- ISO 15765-4 CAN;
- 500 кбит/с;
- 11-bit идентификаторы;
- функциональный OBD-запрос `0x7DF`;
- ответы двигателя обычно `0x7E8–0x7EF`.

Это необходимо проверить на автомобиле. Прошивка должна уметь выполнить первичное обнаружение ECU и поддерживаемых PID.

### 6.3. Первый тестовый запрос

```text
ID:   0x7DF
DATA: 02 01 00 00 00 00 00 00
```

Ожидаемый формат ответа:

```text
0x7E8: 06 41 00 XX XX XX XX 00
```

После обнаружения блока следует последовательно запросить диапазоны поддерживаемых PID:

- `01 00`;
- `01 20`;
- `01 40`;
- `01 60`, если предыдущий диапазон сообщает о продолжении.

### 6.4. Минимальная инициализация TWAI

```cpp
#include <Arduino.h>
#include "driver/twai.h"

#define CAN_TX GPIO_NUM_16
#define CAN_RX GPIO_NUM_17

void setupCan() {
  twai_general_config_t generalConfig =
      TWAI_GENERAL_CONFIG_DEFAULT(CAN_TX, CAN_RX, TWAI_MODE_NORMAL);

  twai_timing_config_t timingConfig =
      TWAI_TIMING_CONFIG_500KBITS();

  twai_filter_config_t filterConfig =
      TWAI_FILTER_CONFIG_ACCEPT_ALL();

  if (twai_driver_install(
          &generalConfig,
          &timingConfig,
          &filterConfig) == ESP_OK) {
    twai_start();
  }
}
```

## 7. Требуемые стандартные OBD PID

| Параметр | Mode/PID | Формула |
|---|---|---|
| Поддерживаемые PID | `01 00` | битовая маска |
| Температура ОЖ | `01 05` | `A - 40`, °C |
| MAP | `01 0B` | `A`, кПа |
| Обороты | `01 0C` | `(256*A+B)/4`, rpm |
| Скорость | `01 0D` | `A`, км/ч |
| MAF | `01 10` | `(256*A+B)/100`, г/с |
| Атмосферное давление | `01 33` | `A`, кПа |
| Напряжение ECU | `01 42` | `(256*A+B)/1000`, В |
| Fuel Rate | `01 5E` | `(256*A+B)/20`, л/ч |

Наличие PID `33`, `10` и `5E` на конкретном Haval требуется проверить. Нельзя проектировать расход, считая их гарантированно доступными.

## 8. Расчёт турбонаддува

PID `0B` показывает абсолютное давление во впускном коллекторе, а не привычное относительное давление турбины.

```text
boost_bar = (MAP_kPa - BARO_kPa) / 100
```

Пример под наддувом:

```text
MAP  = 181 кПа
BARO = 99 кПа
boost = (181 - 99) / 100 = +0.82 bar
```

Пример на холостом ходу:

```text
MAP  = 38 кПа
BARO = 99 кПа
boost = (38 - 99) / 100 = -0.61 bar
```

### Источник атмосферного давления

Приоритетная логика:

1. PID `33` BARO, если поддерживается.
2. MAP при включённом зажигании и заглушенном двигателе.
3. Последнее сохранённое значение.
4. Опциональный BMP280.
5. В крайнем случае фиксированные 100 кПа.

BMP280 не нужен, если Haval стабильно отдаёт PID `33`. Если он будет установлен, корпус должен сообщаться с атмосферой через небольшое отверстие.

## 9. Расход топлива

### 9.1. При наличии Fuel Rate PID 5E

```text
fuel_lph = Fuel Rate
```

Во время движения:

```text
fuel_l_per_100km = fuel_lph * 100 / speed_kmh
```

При скорости ниже примерно 5 км/ч показывать л/ч, потому что л/100 км при нулевой скорости не определён.

### 9.2. Расчёт по MAF

Общая оценочная формула:

```text
fuel_lph = MAF_g_s * 3600 / (AFR * fuel_density_g_l)
```

Для бензина при AFR 14.7 и плотности 745 г/л:

```text
fuel_lph ≈ MAF_g_s * 0.329
```

Это оценка. На турбомоторе при разгоне смесь обогащается, поэтому расчёт по постоянному AFR может занижать расход. В веб-настройках нужен коэффициент калибровки.

### 9.3. Средний расход

Накопление:

```text
liters += fuel_lph * dt_seconds / 3600
kilometers += speed_kmh * dt_seconds / 3600
average_l_per_100km = liters * 100 / kilometers
```

Режимы среднего расхода:

- с запуска двигателя;
- после ручного сброса;
- скользящий за последние N километров.

Запись в Flash не выполнять каждую секунду. Сохранять, например:

- при выключении двигателя;
- раз в 1 км;
- раз в несколько минут;
- при существенном изменении данных.

### 9.4. Особенности ГБО

Стандартный Fuel Rate бензинового ECU при работе на газе может:

- показывать расчётную бензиновую команду;
- показывать неверное значение;
- в некоторых конфигурациях показывать ноль;
- не учитывать реальный расход LPG.

Расчёт LPG по MAF тоже приблизительный, потому что состав пропан-бутановой смеси и плотность топлива меняются. Нужны отдельные коэффициенты:

- коэффициент бензина;
- коэффициент LPG.

Калибровка по заправке:

```text
new_coefficient = old_coefficient * actual_refill / calculated_consumption
```

Следует вести раздельные накопители:

- бензин, литры и пробег;
- LPG, литры и пробег;
- общий пробег поездки;
- время на бензине;
- время на LPG.

Если состояние ГБО определяется только клапаном, одновременный бензиновый довпрыск обнаружить нельзя.

## 11. ГБО BRC Sequent 32 EVO OBD

### 11.1. Что известно

Согласно официальным материалам BRC, Sequent 32 EVO OBD:

- общается и перепрограммируется с ПК через K-Line;
- поддерживает KWP2000;
- поддерживает CAN Bus 2.0 и K-Line;
- имеет диагностику датчиков и исполнительных механизмов;
- работает с датчиком давления газа, температуры газа и MAP.

При этом подключение BRC к автомобильному CAN используется для получения данных автомобиля. Наличие этого подключения не означает, что BRC публикует в CAN своё состояние «газ/бензин» или отвечает на стандартные OBD PID как отдельный ECU.

### 11.2. Первая версия: сигнал клапана

Самый простой надёжный источник бинарного состояния — напряжение на одном газовом электромагнитном клапане.

Универсальная идея входа:

```text
два провода катушки одного клапана
                 │
            диодный мост
                 │
       ограничительный резистор
                 │
             оптопара
                 │
              GPIO34
```

Почему измерять между двумя выводами катушки:

- неизвестно, коммутирует BRC плюс или массу;
- диодный мост делает полярность несущественной;
- отсутствует прямое соединение 12 В с ESP32;
- вход не связывает управляющий провод клапана с массой.

Точную схему, номиналы, TVS и тип оптопары нужно выбрать после измерения напряжений на конкретном автомобиле. Подключаться следует только к одному клапану и не соединять передний и задний выходы BRC между собой.

Программная логика:

```text
RPM = 0                         → двигатель выключен, значок погашен
RPM > 0, клапан неактивен       → бензин, значок «95»
RPM > 0, клапан активен >800 мс → LPG, зелёный значок «LPG»
```

Нужна фильтрация примерно 500–1000 мс и задержка отключения около 1 секунды.

Ограничения:

- клапан сообщает только о том, что газовая магистраль активна;
- он не показывает прогрев, ошибку, низкое давление и остаток газа;
- он не обнаруживает одновременный довпрыск бензина.

### 11.3. Вторая версия: диагностический K-Line BRC

Диагностический разъём BRC отдельный от OBD автомобиля. Для чтения потребуется:

```text
диагностический разъём BRC
           │
K-Line transceiver: L9637D / MC33290
           │ UART
         ESP32
```

Нельзя подключать K-Line напрямую к GPIO ESP32.

Официальный/совместимый кабель BRC обычно имеет отдельный трёхконтактный разъём. Распиновку нельзя определять наугад — её необходимо подтвердить по конкретному жгуту, фото, схеме или измерениям.

KWP2000 определяет транспорт и набор диагностических сервисов, но идентификаторы текущих параметров BRC могут быть фирменными. Для реализации потребуется выяснить:

- способ инициализации;
- адреса ECU;
- скорость обмена;
- заголовки сообщений;
- команды начала диагностической сессии;
- команды Tester Present;
- идентификаторы данных;
- контрольные суммы;
- представление режима топлива, давления и температур.

Практический способ исследования:

1. Использовать рабочий BRC USB-интерфейс и разрешённую фирменную программу.
2. Открыть экран живых параметров.
3. Записать обмен между программой и адаптером либо пассивно снять K-Line защищённым анализатором.
4. Найти периодические запросы и ответы.
5. Сопоставить изменяющиеся байты с переключением бензин/LPG.
6. Сначала реализовать только команды чтения.
7. Не реализовывать запись настроек и перепрошивку BRC без отдельной необходимости.

Одновременная работа фирменной программы и ESP32 как двух мастеров на одной K-Line нежелательна.

Если K-Line будет реализована, потенциально можно получать:

- точный режим бензин/LPG;
- состояние прогрева и перехода;
- давление газа;
- температуру газа;
- температуру редуктора;
- времена бензинового и газового впрыска;
- ошибки ГБО;
- возможно, бензиновый довпрыск.

Даже после появления K-Line вход от клапана рекомендуется оставить как резервный.

## 12. Главный экран GC9A01

Главный принцип: не делать четыре равноправных мелких прибора. Наддув — главный показатель, остальные компактные.

Концепция:

```text
                 13.9 V

          ╭────────────────╮
       ╱                       ╲
      │   внешняя дуга наддува  │
      │                         │
      │          +0.82          │
      │           BAR           │
      │                         │
      │    9.6          8.1     │
       ╲  ТЕКУЩ.       СРЕДН.  ╱
          ╰────────────────╯
```

Дополнительно в верхней части:

- зелёная капсула `LPG`;
- янтарная капсула `95`;
- серый/погашенный индикатор при выключенном двигателе;
- в будущем возможен статус `MIX`, если BRC K-Line позволит определить довпрыск.

Цвет шкалы:

- вакуум — синий/голубой или серый;
- нормальный наддув — зелёный;
- предупреждение — жёлтый;
- опасная зона — красный.

Начальный диапазон шкалы:

```text
-1.0 … +1.5 bar
```

Пороги должны настраиваться через веб, а не быть жёстко зашитыми.

## 14. Шрифты и отрисовка

Стандартные растровые шрифты TFT_eSPI выглядят слишком угловато. Планируется использовать сглаженные пользовательские шрифты.

Предпочтительные открытые шрифты:

- Manrope SemiBold — крупные цифры;
- Inter Medium/SemiBold — подписи и вторичные значения;
- Roboto Condensed — возможная альтернатива для узких областей.

Начальные размеры:

| Элемент | Размер |
|---|---:|
| Центральный наддув | 52–60 px |
| Текущий/средний расход | 22–26 px |
| Напряжение | 20–22 px |
| Единицы | 14–16 px |
| Подписи | не меньше 12–14 px |

Не использовать тонкие начертания.

Шрифты хранить внутри прошивки или LittleFS. Для крупного шрифта достаточно подмножества:

```text
0123456789+-. 
```

Для небольших подписей добавить только фактически используемые русские буквы и единицы. Это уменьшит Flash.

Для TFT_eSPI возможны Smooth Fonts `.vlw`. Отрисовывать желательно через `TFT_eSprite`, чтобы не было мерцания. Полный буфер 240×240 RGB565 занимает около 115 КБ, что допустимо для ESP32 при аккуратном использовании памяти и выключенном Wi‑Fi в штатном режиме.

## 15. Логика одной кнопки

### Штатный режим

```text
короткое нажатие → следующий экран
длинное          → контекстное действие
очень длинное    → сервисный режим, только при остановке
```

### Сброс среднего расхода

Не делать мгновенный сброс. Показывать круговой прогресс:

```text
УДЕРЖИВАЙТЕ ДЛЯ СБРОСА
████████░░
```

- удержание до конца — сброс;
- отпускание раньше — отмена.

### Сервисный режим

- удержание кнопки при включении около 3 секунд;
- либо удержание около 5 секунд при скорости 0;
- выход через длительное удержание или веб-команду;
- автоматический выход по тайм-ауту.

Двойные и тройные клики по умолчанию не использовать: в движении они неудобны.

## 17. Питание

OBD pin 16 часто имеет постоянные +12 В даже при выключенном автомобиле. Нельзя подключать его напрямую к ESP32.

Окончательная цепь:

```text
OBD pin 16
   │
предохранитель
   │
защита от переполюсовки
   │
TVS / защита от автомобильных выбросов
   │
автомобильный DC/DC 12 → 5 В
   │
5V/VIN ESP32 DevKit V1
```

Не рассчитывать на штатный линейный стабилизатор DevKit как на автомобильный вход 12 В. Для настольного теста использовать USB.

Нужно предусмотреть:

- сон после остановки двигателя и исчезновения CAN;
- пробуждение по CAN/напряжению/зажиганию;
- минимальное потребление в выключенном автомобиле;
- отключение Wi‑Fi вне сервисного режима;
- корректное сохранение статистики перед сном.

## 19. Безопасность и ограничения

- Не подключать GPIO ESP32 напрямую к CAN-H/CAN-L.
- Не подавать автомобильные 12 В на GPIO.
- Не использовать непроверенную распиновку диагностического разъёма BRC.
- Не соединять управляющие выходы переднего и заднего клапанов BRC.
- Не добавлять 120 Ом на уже терминированную автомобильную CAN-шину.
- Не разрешать произвольную отправку CAN-кадров из веб-панели.
- На первом этапе использовать только стандартные OBD Mode 01 запросы чтения.
- Не очищать DTC и не выполнять кодирование ECU во время движения.
- Настройки и OTA разрешать только на стоящем автомобиле и при стабильном питании.
- При потере OBD на экране показывать `---`, а не последнее значение как актуальное.
- Корпус и крепление не должны перекрывать обзор и мешать управлению автомобилем.

## 24. Краткое резюме для продолжения в новом диалоге

Проект — круглый автомобильный информационный прибор для Haval H2 2018 1.5T с ГБО BRC Sequent 32 EVO OBD. Аппаратная база: ESP32 DevKit V1 и GC9A01 240×240. Основные показатели: boost, напряжение, текущий/средний расход и LPG/95.

Основной CAN реализовать без MCP2515: встроенный TWAI ESP32, TX GPIO16, RX GPIO17, внешний 3.3-вольтовый CAN-трансивер. GC9A01: SCLK14, MOSI13, CS33, DC27, RST26, подсветка через GPIO25/MOSFET. Кнопка GPIO32. Состояние LPG первой версии — оптопара от одного клапана на GPIO34 с внешней подтяжкой. BRC K-Line/KWP2000 — отдельный будущий этап.

Управление одной кнопкой. Все настройки — через локальный Wi‑Fi сервисный режим и автономную веб-панель. Уже существует интерактивный файл `h2-gauge-web-mockup.html` и конфигурация `h2-gauge-config.example.json`.

Первое реальное действие после возобновления проекта: подключить CAN-трансивер, отправить `01 00`, записать ответ Haval и проверить поддержку PID `0B`, `10`, `33`, `42`, `5E`. До этого не считать способ расчёта расхода окончательно выбранным.
