# H2 Gauge 0.4.2-diag3 — аппаратная web-диагностика

**Дата сборки:** 2026-10-07  
**Цель:** ESP32-S3 DevKitC-1 N16R8 (`esp32s3-n16r8`)  
**Назначение:** временная OTA-прошивка для поиска причин отсутствия ECU/CAN и сигнала LPG  
**Официальный release:** `0.4.2` в каталоге [`../../releases`](../../releases) не заменён и не изменён

`0.4.2-diag3` заменяет диагностические `diag1/diag2`. Она сохраняет исправление реального LPG debounce из `diag2`, показывает чужие запросы `0x7DF` и raw-ответы `0x7E8…0x7EF`, а также реализует выбранную valve-authoritative индикацию: при включённой настройке stable GPIO5 active → `LPG`, inactive → `95`, даже если PID 0C/RPM недоступен. `OFF` имеет приоритет только при достоверном RPM ≤200.

## Что изменено и что не изменено

Диагностическая сборка после каждого запуска автоматически включает Wi‑Fi service mode — удерживать GPIO4 не требуется. В отличие от обычного service mode, штатный read-only OBD Mode 01 polling остаётся активным, чтобы были видны TX/RX, discovery и выбор engine ECU.

Добавлены только диагностическая web-страница и read-only снимки:

- GPIO4/5/6/7/10/11/12/13/14/16/17;
- LPG GPIO5: raw level, active-low преобразование, фактические candidate/debounce/stable состояния `LpgValveInput`, глобальный `lpgEnabled`;
- выбранное топливо `LPG/95` и источник решения (`stable_gpio5_valve`, `rpm_off` или fallback);
- TWAI: состояние, очереди, TEC/REC, TX failures, bus errors, missed/overrun, arbitration lost и bus-off;
- последние TX/RX CAN frames и счётчики;
- отдельные счётчики RX `0x7DF` (другой активный OBD-клиент) и raw `0x7E8…0x7EF` replies;
- OBD: текущий запрос/PID, discovery, ожидание, ответы, timeout и lock engine ECU.

Прошивка **не добавляет произвольную передачу CAN**. Выполняется тот же штатный read-only Mode 01 polling. Защита ручного Mode 04 не изменена; для этой проверки Mode 04 не запускайте.

## Установка через существующий OTA

1. Поставьте автомобиль, включите стояночный тормоз, селектор — `P`/нейтраль. Во время OTA не двигайтесь.
2. На текущей прошивке войдите в обычный service mode и подключитесь к Wi‑Fi `H2-Gauge-XXXX`.
3. Откройте `http://192.168.4.1`. Если телефон уходит в мобильный интернет, временно отключите мобильные данные/VPN, но оставьте Wi‑Fi H2 Gauge.
4. В разделе обновления выберите `h2-gauge-v0.4.2-diag3-esp32s3-n16r8.bin`.
5. Подтвердите OTA и дождитесь **100%, проверки образа и автоматической перезагрузки**. Не выключайте питание и не нажимайте `EN` во время записи.
6. После reboot заново подключитесь к `H2-Gauge-XXXX` и откройте `http://192.168.4.1`.
7. В верхней строке должно быть `0.4.2-diag3 / esp32s3-n16r8`. Если показана другая версия, диагностику не начинайте.

Главная страница `/` — диагностика. Ссылка **«Обычный интерфейс»** ведёт на `/normal`, где остаются штатные настройки и OTA.

## Обязательная автомобильная проверка

Проверку выполняйте только на неподвижном автомобиле. Для включения BRC/LPG двигатель, вероятно, должен работать; не проводите тест в закрытом помещении без безопасной вентиляции.

### 1. Сначала — зажигание и открытая web-диагностика

1. Включите зажигание. Если для работы BRC нужен запущенный двигатель, запустите его, но автомобиль не двигайте.
2. Сразу откройте `http://192.168.4.1` и оставьте страницу открытой: она обновляется примерно раз в секунду.
3. Подождите 10–15 секунд, чтобы OBD discovery успел пройти несколько запросов.
4. Зафиксируйте скриншотом:
   - **GPIO — текущие уровни**;
   - **TWAI controller**;
   - **CAN activity**;
   - **OBD discovery**;
   - **Последние CAN кадры**;
   - **Быстрый итог**.
5. Дополнительно откройте и сохраните/скопируйте raw JSON:
   - `http://192.168.4.1/api/diagnostics/hardware`
   - `http://192.168.4.1/api/can/snapshot`

### 2. Снимок при выключенном ГБО / работе на бензине

1. Переведите BRC в состояние **газовый клапан OFF / бензин**.
2. Нажмите **«Очистить CAN snapshot»**.
3. Подождите 5–10 секунд.
4. Зафиксируйте те же шесть секций и оба raw JSON.
5. Для стандартного active-low входа ожидается:
   - GPIO5 `rawLevel=1`;
   - `electricalActive=false`;
   - `candidateElectricalActive=false`;
   - после задержки `stableElectricalActive=false`;
   - `lpgEnabled=true`, если ГБО глобально разрешено в настройках.

При выключении газа stable может некоторое время оставаться `true`: реальный порог OFF равен `lpgDebounceMs + lpgOffDelayMs` (по умолчанию `800 + 1000 = 1800 мс`). Это нормальная задержка, а не ошибка.

### 3. Снимок при включённом ГБО

1. Включите BRC и дождитесь подтверждения фактического перехода на LPG/открытия клапана.
2. Наблюдайте строку **LPG / PC817** во время перехода:
   - GPIO5 для active-low должен перейти `rawLevel: 1 → 0`;
   - `electricalActive` и `candidateElectricalActive` должны стать `true` сразу;
   - `debounceSatisfied` станет `true` после требуемого интервала;
   - затем `stableElectricalActive=true`;
   - `lpgEnabled` должен оставаться `true`.
3. После стабилизации нажмите **«Очистить CAN snapshot»**, подождите 5–10 секунд и снова зафиксируйте все секции и оба raw JSON.
4. Если индикатор BRC показывает LPG, а GPIO5 остаётся HIGH/`false`, проверяйте PC817, общий провод логической стороны, внешний pull-up 10 кОм, полярность входа и связь с сигналом клапана.

## Как читать результат CAN/OBD

| Наблюдение | Наиболее вероятное направление проверки |
|---|---|
| `TWAI state=running`, TX растёт, RX растёт, OBD responses растут, ECU `locked` | Физический CAN и Mode 01 работают; проблема не в полном отсутствии связи |
| TX есть, RX=0, растут `txFailedCount`/`busErrorCount`/TEC или появляется `bus_off` | CANH/CANL, питание/земля SN65HVD230, CTX/CRX, bitrate 500 кбит/с, терминация |
| RX frames есть, но OBD responses=0 и ECU не locked | Кадры на шине принимаются, но нет принятого ответа Mode 01 PID 0C; важны ID/data и timeout |
| TX=0 при `readOnlyPollingActive=true` | Проверять состояние TWAI/OBD state machine и `pendingRequest` |
| `TWAI status unavailable` | Драйвер не поднялся либо уже остановлен; сохранить весь hardware JSON |
| Только GPIO16/17 меняются или постоянно HIGH | Само по себе ничего не доказывает: web читает мгновенный уровень и не видит быстрые CAN-импульсы |

Для сравнения OFF/ON нужны именно счётчики TWAI, retained TX/RX и таблица кадров. Мгновенные уровни GPIO16/17 и GPIO13/14 не заменяют осциллограф.

## Что прислать для разбора

Минимальный комплект:

1. скрин/JSON после первого открытия с зажиганием;
2. скрин/JSON при LPG OFF;
3. скрин/JSON при LPG ON;
4. указать, был ли двигатель запущен и что показывал переключатель BRC;
5. отдельно записать: GPIO5 raw/candidate/stable, TWAI state/TEC/REC/errors, TX/RX counts, pending PID, response/timeout counts и ECU ID/lock.

## Возврат на официальный 0.4.2

После завершения диагностики:

1. откройте `http://192.168.4.1/normal`;
2. в OTA выберите официальный `releases/h2-gauge-v0.4.2-esp32s3-n16r8.bin`;
3. дождитесь проверки и автоматического reboot;
4. подтвердите в service UI текущую сборку `0.4.2` и версии обоих OTA-слотов.

Не используйте factory image для возврата через web OTA. App-only переход сохраняет NVS, настройки, trip, калибровки, DTC history, LittleFS journal и пользовательские ресурсы.
